## 🛡️ The Three Pillars of Cryptography
Cryptography is used to provide **Confidentiality, Integrity, and Non-repudiation.**

### 1. Hashing (Integrity)
A one-way mathematical function that turns data into a fixed-length string of characters. 
* **Key Feature:** It cannot be reversed. If even one bit of the original data changes, the "hash" changes completely (The Avalanche Effect).
* **Common Algorithms:**
    * **SHA-256 / SHA-3:** The current standard.
    * **MD5:** Older, fast, but now considered insecure due to "collisions."
* **Use Case:** Verifying that a file downloaded from the internet hasn't been tampered with.

### 2. Symmetric Encryption (Confidentiality)
Uses the **same key** to both encrypt and decrypt the data.
* **Key Feature:** Very fast and efficient for large amounts of data.
* **The Challenge:** How do you securely share the key with the recipient? (Out-of-band distribution).
* **Common Algorithms:**
    * **AES (Advanced Encryption Standard):** The industry gold standard (128, 192, and 256-bit).
    * **DES / 3DES:** Legacy; no longer considered secure for modern use.

### 3. Asymmetric Encryption (Confidentiality & Non-repudiation)
Uses a **Key Pair**: a **Public Key** (shared with everyone) and a **Private Key** (kept secret).
* **How it works:** Data encrypted with the Public Key can *only* be decrypted by the matching Private Key.
* **Common Algorithms:**
    * **RSA:** Based on large prime numbers.
    * **ECC (Elliptic Curve Cryptography):** Provides the same security as RSA but with much smaller keys (faster, better for mobile devices).

## 🗝️ Public Key Infrastructure (PKI)
PKI is the entire system of hardware, software, people, and policies used to create, manage, and revoke digital certificates.



| Component | Description |
| :--- | :--- |
| **Certificate Authority (CA)** | The trusted third party that issues and signs digital certificates. |
| **Registration Authority (RA)** | Verifies the identity of the person requesting a certificate before the CA issues it. |
| **CRL (Cert. Revocation List)** | A list of certificates that have been cancelled before their expiration date. |
| **OCSP (Online Cert. Status Protocol)** | A faster, real-time way to check if a certificate is still valid. |

---

## 🔐 Advanced Concepts
* **Digital Signatures:** Provides **Integrity** and **Non-repudiation**. The sender hashes a message and encrypts the hash with their *Private Key*. The recipient decrypts it with the sender's *Public Key*.
* **Key Stretching:** Making a weak password stronger by running it through a hashing algorithm thousands of times (e.g., **bcrypt**, **PBKDF2**).
* **Salting:** Adding random data to a password before hashing it to prevent **Rainbow Table** attacks.
* **Quantum Concerns:** Modern encryption (like RSA) is vulnerable to future quantum computers. **Post-Quantum Cryptography (PQC)** is the research into algorithms that can survive a quantum attack.

## 🔑 Key Acronyms
| Acronym | Full Name | Description |
| :--- | :--- | :--- |
| **ECC** | Elliptic Curve Cryptography | High security with small key sizes; great for mobile/IoT. |
| **HSM** | Hardware Security Module | A physical device used to safeguard and manage digital keys. |
| **PFS** | Perfect Forward Secrecy | Ensures that if a long-term key is compromised, past session keys remain secure. |

## 💡 Exam Tip
> [!IMPORTANT]
> **Encryption vs. Hashing:** If the question mentions "Integrity" or "Digital Signatures," think **Hashing**. If the question mentions "Privacy" or "Secret," think **Encryption**. 
> **ECC vs. RSA:** If the question asks for the best encryption for a "resource-constrained device" (like a phone or smart watch), the answer is always **ECC**.
